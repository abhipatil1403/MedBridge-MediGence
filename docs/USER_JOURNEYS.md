# User journeys

These are MedBridge target workflows derived from the [public reference audit](MEDIGENCE_REFERENCE_AUDIT.md). Authenticated and transaction steps are designs to validate, not claims that MediGence was operated end to end. Every step persists a case/event ID where appropriate, shows a current state, and gives one explicit next action. Medical choices remain with qualified professionals.

| Journey | Path and handoffs | Decision points, failure recovery and completion |
|---|---|---|
| 1. Unknown need | Patient writes an everyday description at `/discover` → DiscoveryAgent identifies possible intent and asks only missing location/goal questions → retrieves reviewed treatment concepts → shows possible procedures as **topics to discuss**, available destination/provider options and sourced cost ranges → patient chooses compare, consult, or create case. | If intent is clinically ambiguous, avoid diagnosis and offer clinician review. No provider/price source means show no invented recommendation and open a coordinator request. Completion is a saved shortlist or initiated service, not a medical decision. |
| 2. Treatment discovery | Search → treatment directory → treatment detail with reviewed overview → relevant countries → hospitals/doctors → dated costs → eligible packages → enquiry/case. | Changing country updates all linked lists. Empty inventory keeps educational content but removes booking promises. Cost estimates show currency, inclusions and last verified date. |
| 3. Hospital discovery | Search or country/treatment link → filters → hospital list → profile → specialties/procedures and affiliated doctors → cost/package where actually offered → request quote. | Accreditation requires current evidence; stale or absent evidence is labelled. If the hospital cannot treat selected procedure, explain why it is excluded. Quote request becomes a tracked case. |
| 4. Doctor consultation | Doctor search → filters → verified profile → live slot in patient's timezone → patient details/consent → documents → order/payment → booking confirmation → video session → clinician notes and follow-up. | Slot hold expires safely. Payment succeeds but booking fails: reconcile and refund or reschedule; never double charge. No slots: alternate clinicians or waitlist. Emergency symptoms are directed to local emergency care, not a delayed online booking. |
| 5. Second opinion | Landing or case CTA → registration → patient profile → condition, symptoms, diagnosis status, history and investigations → secure documents/DICOM → service/country preference → review of submitted information → payment → clinical completeness check → reviewer assignment → signed report → optional video consultation → patient follow-up. | Draft survives interruption. Missing records cause a clear request; failed scan prevents review. AI summary is marked draft until clinician checks it. Payment state is reconciled before assignment. Report is versioned, downloadable only by authorized users, and never AI-signed. |
| 6. Medical travel | Treatment → destination → provider → reviewed treatment plan and quote → visa requirements/request → flights and accommodation requests → transfer/companion needs → confirmed itinerary → admission → treatment milestones → discharge and recovery handoff. | Each logistics item distinguishes requested, quoted and confirmed. A visa delay or treatment date change triggers a coordinator task and itinerary revision. No flight/visa is shown as booked from an unconfirmed request. |
| 7. Recovery | Discharge event → clinician-approved recovery plan → dated rehabilitation/physiotherapy/nutrition/follow-up tasks → patient check-ins → concerning or missed response escalated to care team → local-doctor handover with consent → plan completion. | A monitoring alert requires clinical protocol and human escalation. If patient stops responding, show last contact and owner; do not fabricate progress. Completion includes clinician signoff and handover status. |
| 8. Country comparison | Choose procedure → country A/B → normalized and sourced cost range → hospital/doctor options → quality evidence, travel/visa and stay inputs → personal preference weighting → comparison saved to case. | Missing a country's comparable offer yields a partial table, not a guessed value. Cost basis, exchange date, provider source, uncertainty and exclusions appear alongside values. User may request a verified custom quote. |
| 9. Package booking | Package discovery → offer detail → inclusions/exclusions and validity → linked hospital and confirmed clinician if named → optional travel services → patient details → provider confirmation → order/payment → booking reference → coordinator tasks. | Expired offers cannot be checked out. Reconfirm dates and medical eligibility before collecting payment. Partial payment, provider rejection and refund paths are explicit. |
| 10. Returning patient | Login → dashboard active case → current stage and next action → appointments/documents/messages/payment/travel/recovery, each with timestamp and owner → complete task → status updated. | No active case shows a useful discovery path. Access expired: reauthenticate and return to intended page. A case with no pending patient action explains what the care team is doing and when it last changed. |

## Implemented assistant planning journey

At `/assistant`, “I need knee replacement treatment in Mumbai” creates a saved coordination plan and uses existing catalog tools to find hospitals and packages. Including doctors adds a doctor search. Simple discovery such as “heart doctor in Mumbai” remains a DiscoveryAgent request. Unsupported procedures retain zero-exact-match behavior and do not create a false provider plan.

“Show me packages” or “Which hospitals do we have?” continues the same plan using saved treatment/location criteria. Identical successful searches reuse sourced findings; changing a USD budget refreshes the affected package search. The panel records actual search completion, pending reviews, optional preferences, and confirmation states. Users mark reviews/preferences done, reopen them, or cancel a plan. Refresh reloads the selected conversation and saved plan. Completion describes the coordination checklist, not treatment, booking, or provider contact.

## Implemented assistant comparison journey

“Compare knee replacement in Pune and Mumbai” keeps the two locations in that order and searches each independently. A location with no published matching records remains empty; the other side retains its sourced results. Hospital/package/doctor table values come from validated findings. Source details retain record IDs, dates, match reasons and synthetic labels. Package prices are listed samples, not quotes or clinical recommendations.

“Which has the cheaper package?” reuses the saved comparison subject and options. If either side lacks a comparable price, the assistant reports the available price and the missing side without declaring a cheaper destination. A stated USD budget filters package searches only. “Compare it with Pune” after a Mumbai treatment plan adds the comparison to that same plan; it does not replace its destination. Missing subjects or second options produce one clarification and no provider search. Refresh restores the comparison from the conversation and care-plan task. On mobile, each comparison table scrolls inside its own labeled region.

## Cross-journey invariants

Catalog follow-ups now resolve against saved structured results: “the second hospital”, “the Mumbai one” and “that package” preserve displayed order and identity across refresh. Multiple plausible records or an ordinal outside the shown list prompt clarification. After a hospital detail, “Show me its package” searches only packages linked to that hospital and the active plan criteria. Relative prices/durations use complete comparable listed values; missing comparison-side prices cannot produce a cheaper destination. Normal explicit discovery, planning and comparison queries retain their existing routes.

For “I need knee replacement in Mumbai, under $6,000, and I want a package with accommodation”, a package's treatment, destination, budget and existence are checked separately from accommodation. The catalog's hospital stay does not establish accommodation: the UI shows “Not specified”, explains the missing evidence and retains the useful package. “Does the package include accommodation?” reads that package's evidence; “Show me another package” keeps the criteria without inventing an alternative. “What about Pune?” changes destination while retaining budget/package/features. Comparisons show separate evaluations per destination, and saved requirements remain visible after refresh.

- A person may have several cases; a service request belongs to one case and one patient profile. A caregiver needs an explicit grant, not a shared login.
- Each action has an actor, timestamp, state transition and idempotency key where it can be retried. Notifications are consequences of persisted events.
- Patient-reported facts, imported records, AI drafts and clinician conclusions are separate fields and visually distinct.
- A saved comparison is informational; a treatment plan, offer, booking and payment each require their own confirmation.
- Case ownership and next action are visible to patient and staff. Exceptions are tasks, not silent dead ends.
